## 恢复开发时的阅读顺序

1. 先读本仓库的 [暂停交接](../../../DEVELOPMENT_PAUSE.md)，核对暂停时成果、未完成与待验收事项。
2. 阅读功能现状总览，再按项目阅读需求分册或完整稿。
3. 回到本仓库正式需求、共同需求采用说明、当前 Git 状态和真实验证证据，重新核对差距。
4. 由用户明确恢复范围后再开展新开发；汇编中的历史下一步不是恢复授权。

## 文档定位

这些文档是固定日期的阅读汇编。需求描述不代表功能已实现，技术验证不代表业务验收；原文版本及采用范围按各仓库正式记录处理。需求汇编内的 GitHub 原文链接固定到原提交，私有仓库链接仍要求相应访问权限。

本次只同步文档与导航。开发暂停继续有效，现有日常运营任务按原配置保持。完整稿、现状总览与原始需求文件均保留，不以分册替代或改写历史记录。
